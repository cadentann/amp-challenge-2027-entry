# AMP Challenge 2027 — AMP-Prompt + `CONSENSUS_FIXED` entry

Peptides generated by the publicly released **AMP-Prompt** soft-prompt generator and ranked by a
**frozen consensus selector** over two independent antimicrobial-activity predictors, APEX and
ANIA. The submitted top-100 is selected from all 48,133 eligible members of a 50,000-peptide
library.

**Every result in this repository is a computational prediction. No peptide here has been
synthesised or assayed. Safety, haemolysis and selectivity are unknown.**

## Running it

A fresh clone does not contain model weights. The AMP-Prompt checkpoint (315 MB, Zenodo) and the
APEX/ANIA evaluator assets (235 MB, GitLab and GitHub) are third-party artifacts that are
retrieved from their published sources rather than redistributed here. One script does that,
verifying every byte against a hash pinned in this repository before it is used:

```console
uv sync
uv run python scripts/prepare_entry.py
uv run --no-sync generate --preflight-only
uv run --no-sync generate
```

`prepare_entry.py` downloads roughly 550 MB, verifies all 62 pinned evaluator files plus the
generator checkpoint, builds the isolated Python 3.10 scorer runtime, and installs the
cross-evaluator equivalence receipt for the host platform. It is idempotent and resumable. It
fails closed: if any upstream source no longer serves the pinned bytes, it stops rather than
proceeding with different assets.

Generation writes `generate/library.fasta` and `generate/top.fasta`. The preflight loads no
biological model and performs no inference. Expect roughly 50 minutes on an RTX 4090; scoring
48,133 candidates on CPU dominates that time.

**Hardware note.** The shipped artifacts were generated on an RTX 4090 with CUDA 12.8. Repeat
execution on that device is byte-identical. A different GPU will produce different sequences —
normal for a sampling generative model, but it means these files reproduce on equivalent
hardware, not on any hardware.

## Fixed behavior

- authentic AMP-Prompt reconstruction, with an exact audit of all 174 checkpoint tensors and the
  restored learned embedding;
- one RNG initialization per invocation and a continuous stream of native 128-row batches;
- exactly 50,000 accepted, unique, canonical sequences of length 8–50, with no case conversion,
  trimming, clipping, residue substitution or other repair;
- a prospectively locked raw-attempt ceiling of 65,536;
- top eligibility decided before any score is read;
- the byte-identical frozen `CONSENSUS_FIXED` selector and its fixed 996-member anchor;
- run-ID staging, with directory replacement only after both FASTA outputs pass internal
  cardinality and subset checks.

Settings are pinned in `FINALIST.lock.json`, which is tracked in this repository. The entry point
fails closed without it.

## Two environments

The generator and evaluator deliberately use separate environments. The root `uv.lock` freezes the
Python 3.12 / Torch 2.8 generator. `vendor/scorer_subproject/uv.lock` freezes the Python 3.10 /
Torch 2.5.1 CPU evaluator. `scoring_adapter.py` launches the evaluator in a subprocess with
`PYTHONHASHSEED=0` and `CUDA_VISIBLE_DEVICES=''`, so importing scorer code can never reach the
generator GPU.

The scorer runtime reaches `READY_VALIDATED` only with a separately hashed receipt showing all
eight exact APEX member arrays in their fixed order, the exact APEX ensemble, exact ANIA arrays,
exact joined rows and stable row order against the reference evaluator. Receipts for the two
validated platforms ship in `validation/`; on any other platform the runtime stays pending and the
entry refuses to score.

Scorer input order is part of the numerical contract. The full-library universe retains its
top-eligible generation order; the pipeline sends that exact unique order to the scorer, which
neither sorts nor deduplicates it. A retained 1,000-row permutation audit found exact native-R
versus portable equality on identical input, while changing batch composition changed some float32
values — so score evidence binds the complete ordered list and its 32-row batch partitions.

The shipped evaluator is **R-free**: it reproduces the native R-backed evaluator exactly across
510,000 values on macOS and again on Linux. No R installation is required.

## What is verified

- Two clean `uv run generate` runs on a fresh machine: byte-identical, both matching the shipped
  artifacts (`validation/END_TO_END_VALIDATION.json`).
- All four unchanged official validator checks pass.
- Cross-evaluator equivalence on both validated platforms (`validation/`).
- Portability is a **decision-stability** certificate, not bit-equivalence. Byte-exact macOS↔Linux
  equality failed and is retained as a failure; what passed is that predicted values agree within a
  pre-registered 1e-4 log10 MIC budget and every activity label, breadth numerator and tested
  selector ordering is identical.
